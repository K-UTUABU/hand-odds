# 0002 検算の順番を「実装の前」から「公開の前」に変える

- 日付：2026-11-17
- 決めた人：依頼者（提案）、作り手（条件を追加）

## 背景

設計書では「検算表が先、実装が後」としていた。依頼者が手計算で正解を出し、それが届いてから、作り手が計算を実装する順番である。

入力の検査・画面の状態・入力の画面の 3 つは、検算表がなくても作れるので先に済ませた。残りの 4 つの作業（厳密な計算、シミュレーション、結果の表示、公開）は、すべて検算表の記入待ちで止まっていた。

## 決めたこと

- 計算の実装は、検算表を待たずに進める。
- 依頼者が検算表を記入し終えるまで、作り手は計算の結果の数値を依頼者に見せない。テストの出力や、プルリクエストの説明に出る確率の値も含む。
- 検算表の全件がテストで通るまで、公開しない。
- 検算表を作り手が勝手に変えない、という決まりは変えない。

## 理由

- 待ち時間がなくなる。
- 実装中の誤りは、検算表がなくても 2 つのテストで見つけられる。
  - 厳密な計算とシミュレーションの突き合わせ。
  - 計算の性質を確かめるテスト。確率の合計が 1 になること、重なるパターンを二重に数えないことなど。
- 「作り手が作り、発注側が独自の基準で検収する」という受入テストの形になる。依頼者の業務経験とも合う。
- 条件を足した理由：ツールの数字を先に見てから手計算すると、合っていると確かめる方向に引っ張られ、独立した確認ではなくなる。

## 捨てた案

- **元のまま、検算表を待つ。** 確実だが、依頼者の都合で全体が止まる。
- **先に作り、検算は依頼者が画面で値を見てから行う。** 早いが、検算が答え合わせになり、受入テストとしての価値がなくなる。
