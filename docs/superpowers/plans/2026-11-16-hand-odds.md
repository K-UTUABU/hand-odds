# 初手の確率計算ツール 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** デッキをグループに分けて枚数を入れると、初手で条件を満たす確率を、厳密な計算とシミュレーションの両方で出す静的サイトを作る。

**Architecture:** 計算（`src/calc/`）は React を import しない純粋な関数で、単体でテストする。画面（`src/ui/`）は1枚で、状態は `useReducer` 1つにまとめる（`src/state/`）。作業は GitHub の課題1件＝ブランチ1本＝プルリクエスト1件で進め、取り込むのは依頼者だけ。

**Tech Stack:** Vite 8 / React 19 / TypeScript 7 / Tailwind CSS 4 / Vitest 5 + React Testing Library / oxlint / GitHub Actions / GitHub Pages。バージョンは家計簿（`D:\kakeibo\frontend\package.json`）と同じ系列を使い、導入時に `npm view <名前> version` で最新の安定版を確認する。

**Spec:** `docs/superpowers/specs/2026-11-16-hand-odds-design.md`（実行する人は、この計画と設計書の両方を読む）

## Review Focus

設計書が直接は書いていないが、使う人が踏みやすい入力。それぞれ、持ち主のタスクにテストを入れてある。

1. **数値の欄を空にした瞬間・小数・負の数**：`NaN` や `-0.00%` を出さず、その欄の近くに誤りを示し、確率は表示しない（タスク1、タスク5）
2. **グループの合計がデッキ枚数ちょうど（その他が 0 枚）**、**引く枚数がデッキ枚数と同じ**：落ちずに正しい値（0 か 1 を含む）を返す（タスク2）
3. **上限いっぱいの入力**（デッキ 100・引く 10・グループ 10・パターン 6）：厳密な計算がテストで 1 秒以内に終わり（手元での目標は 200 ミリ秒。自動チェックの機械は遅く、ばらつくため幅を持たせる）、全組み合わせの合計が 1 になる（タスク2）
4. **グループを削除・追加したあとのパターン**：消したグループの条件が残って計算に混ざらない。追加したグループは全パターンに条件なしで現れる（タスク4）
5. **厳密な値が 0% または 100% のときのシミュレーション**：誤差の目安が 0 になっても警告を誤って出さない。シミュレーションの値も 0 または 1 ちょうどになる（タスク3、タスク6）

## 共通の型（`src/calc/types.ts`）

全タスクがこの名前を使う。タスク1で作る。

```ts
export const LIMITS = {
  deckMax: 100, handMax: 10, groupMax: 10, patternMax: 6, trials: 100_000,
} as const

export type Group = { id: string; name: string; count: number }
/** max が null のときは上限なし */
export type Condition = { min: number; max: number | null }
/** conditions のキーは Group.id。キーがないグループは条件なし（min 0, max null）として扱う */
export type Pattern = { id: string; name: string; conditions: Record<string, Condition> }
export type DeckInput = { deckSize: number; handSize: number; groups: Group[]; patterns: Pattern[] }

/** patterns[i] は DeckInput.patterns[i] の成立確率（0〜1）。any は「どれか1つでも成立」 */
export type Probabilities = { patterns: number[]; any: number }

/** field の例：'deckSize' / 'handSize' / 'groups' / `group:${id}` / `pattern:${patternId}:${groupId}` */
export type InputError = { field: string; message: string }
```

誤りの文言（この文字列のまま使う）：

| 条件 | field | message |
|---|---|---|
| デッキ枚数が整数でない、または 1〜100 の外 | `deckSize` | `デッキ枚数は 1〜100 の整数で入力してください` |
| 引く枚数が整数でない、または 1〜10 の外 | `handSize` | `引く枚数は 1〜10 の整数で入力してください` |
| 引く枚数がデッキ枚数より多い | `handSize` | `引く枚数はデッキ枚数以下にしてください` |
| グループの枚数が 0 以上の整数でない | `group:${id}` | `枚数は 0 以上の整数で入力してください` |

### Task 2: 厳密な計算

**変更（2026-11-17）：** 検算表を待たずに始める（判断の記録 0002）。`src/calc/kensan.test.ts`（Step 1）は、依頼者が検算表を記入したあとで別のプルリクエストとして作り、タスク7の前に必ず通す。判断の記録の番号は 1 つずつずれ、厳密な計算は 0003、シミュレーションは 0004 になる。

**Files:**
- Create: `src/calc/exact.ts`, `docs/decisions/0002-exact-calculation.md`
- Test: `src/calc/kensan.test.ts`, `src/calc/exact.test.ts`

**Interfaces:**
- Consumes: `DeckInput`, `Probabilities`, `Condition`（タスク1）
- Produces:
  - `exact(input: DeckInput): Probabilities` — 前提：`validate(input)` が空
  - `matches(pattern: Pattern, groups: Group[], counts: number[]): boolean` — `counts[i]` は `groups[i]` を引いた枚数。タスク3も使う

計算の方法（判断の記録 0002 に理由とともに残す）：

```
その他の枚数 R = deckSize − Σ count
初手の内訳 (k_1..k_g, r) を、k_i ≦ count_i、r ≦ R、Σk_i + r = handSize の範囲ですべて列挙する
内訳の重み w = Π C(count_i, k_i) × C(R, r)            ← BigInt で計算する
分母 D = C(deckSize, handSize)                         ← BigInt
パターン j の分子 = パターン j を満たす内訳の w の合計
any の分子       = いずれかのパターンを満たす内訳の w の合計（内訳ごとに1回だけ足す）
確率 = Number(分子 × 10^15 / D) / 10^15
```

パターンごとの確率を足して any を作らない。二項係数は、必要な範囲を一度だけ表にして使い回す。
列挙は再帰で行い、重みは途中までの積を引き継ぐ（内訳ごとに最初から掛け直さない）。
実装後に手元で時間を測り、200 ミリ秒を超えるなら判断の記録 0002 に書いて依頼者に報告する。

- [ ] **Step 2: 性質のテストを書く（`src/calc/exact.test.ts`）**

```ts
const group = (id: string, count: number): Group => ({ id, name: '', count })
const pattern = (id: string, conditions: Pattern['conditions']): Pattern => ({ id, name: '', conditions })

test('条件なしのパターンは確率 1（全内訳の合計が 1）', () => {
  const input = { deckSize: 40, handSize: 5, groups: [group('a', 9), group('b', 6)], patterns: [pattern('p', {})] }
  expect(exact(input).patterns[0]).toBe(1)
})

test('成立しえない条件は 0', () => {
  const input = { deckSize: 40, handSize: 5, groups: [group('a', 4)],
    patterns: [pattern('p', { a: { min: 5, max: null } })] }
  expect(exact(input)).toEqual({ patterns: [0], any: 0 })
})

test('「1枚以上」と「0枚」は足して 1', () => {
  const groups = [group('a', 9)]
  const r = exact({ deckSize: 40, handSize: 5, groups, patterns: [
    pattern('p1', { a: { min: 1, max: null } }), pattern('p2', { a: { min: 0, max: 0 } })] })
  expect(r.patterns[0] + r.patterns[1]).toBeCloseTo(1, 9)
  expect(r.any).toBe(1)
})

test('重なるパターンの any は、足し合わせより小さく、どちらよりも小さくない', () => {
  const groups = [group('a', 9), group('b', 6), group('c', 6)]
  const r = exact({ deckSize: 40, handSize: 5, groups, patterns: [
    pattern('p1', { a: { min: 1, max: null }, b: { min: 1, max: null } }),
    pattern('p2', { a: { min: 1, max: null }, c: { min: 1, max: null } })] })
  expect(r.any).toBeLessThan(r.patterns[0] + r.patterns[1])
  expect(r.any).toBeGreaterThanOrEqual(Math.max(...r.patterns))
```

### Task 3: シミュレーションと突き合わせ

**Files:**
- Create: `src/calc/simulate.ts`, `src/calc/compare.ts`, `docs/decisions/0003-simulation.md`
- Test: `src/calc/simulate.test.ts`, `src/calc/compare.test.ts`

**Interfaces:**
- Consumes: `exact`, `matches`（タスク2）、`LIMITS.trials`
- Produces:
  - `simulate(input: DeckInput, options: { trials: number; seed: number }): Probabilities` — 同じ種なら同じ結果
  - `margin(p: number, trials: number): number` — `3 * Math.sqrt(p * (1 - p) / trials)`。`p` は厳密な値
  - `withinMargin(exactValue: number, simulated: number, trials: number): boolean` — `Math.abs(差) <= margin + 1e-12`

方法：デッキをグループの番号の配列（その他は別の番号）で表し、先頭の `handSize` 枚だけを入れ替えで選ぶ（Fisher–Yates の途中まで）。乱数は種つきの mulberry32。`Math.random` は使わない。成立の判定は `matches` を使う。
